# Github Pull Request 작성

> 이 스킬은 절차와 멘트 규격만 정의한다.
>
> 작성 규칙은 원본 지침 문서에 있다. 각 단계에서 지정된 섹션을 읽고 그 규칙을 따른다. 규칙을 이 문서에 옮겨 적지 않는다.

## 참조 문서

| 문서 | 읽을 섹션 | 용도 |
| --- | --- | --- |
| `Docs\Claude\WorkFlowRules.md` | `7. PR 작성`, `8. 사용자 검수 (PR)` | 작성 절차, 생성 이후 규칙 |
| `Docs\Context\GitConvention.md` | `(3) Pull Request 컨벤션` | PR, 머지 규칙 |
| `Docs\Template\PullRequestTemplate.md` | 상단 안내 ~ `확인 순서` | 제목 태그, PR 본문 양식, 섹션별 작성 규칙 |

## 절차

### 1. 사전 확인

- `WorkFlowRules.md` 의 `7. PR 작성` 을 읽는다.
- 현재 브랜치가 원격에 Push 되어 있는지, 로컬에 Push 되지 않은 커밋이 없는지 확인한다.
- 확인되지 않으면 `멘트 ① Push 요청` 으로 요청하고, 사용자가 Push 할 때까지 진행하지 않는다.

### 2. 정보 수집

- 대상 브랜치(`main` / `Develop`)와 관련 이슈 번호를 확인한다. 명령에 없으면 사용자에게 질문한다.
- 관련 이슈가 있으면 `gh issue view` 로 이슈의 DoD 를 읽는다.
- 대상 브랜치와의 변경 내역(커밋, 변경 파일)을 읽고, 생성 / 수정된 스크립트를 파악한다.
- 변경 내역만으로 알 수 없는 내용 (구현 이유, 확인 순서 등) 은 추측하지 않고 사용자에게 질문한다.

### 3. 초안 작성

- `PullRequestTemplate.md` 양식에 맞춰, 각 섹션의 작성 규칙에 따라 작성한다.
- 제목은 `PullRequestTemplate.md` 상단 안내의 태그를 붙여 `[태그] 작업 내용` 형식으로 작성한다.
- `요청 전 확인사항` 중 Claude 가 직접 확인하지 못한 항목 (콘솔 에러 등) 은 체크하지 않고, 초안에 "미검증" 으로 표기해 사용자에게 확인을 요청한다.
- 초안은 `멘트 ② 생성 전 승인 요청` 으로 보여준다.

### 4. 생성

- 승인을 받은 뒤에만 생성한다.
- `gh pr create` 로 생성하고, Assignee 는 사용자로 지정한다.
- 생성 결과는 `멘트 ③ 생성 완료 보고` 로 보고한다.
- PR 의 승인과 머지는 하지 않는다. (`WorkFlowRules.md` 의 `8. 사용자 검수 (PR)`)

## 멘트 규격

> 불필요한 서술 없이 아래 형식만 사용한다. 해당 없는 줄은 생략한다.

### ① Push 요청

```markdown
**Push 필요** : [브랜치명]
- 사유 : [원격 브랜치 없음 / Push 되지 않은 커밋 N개]
Push 후 알려주세요.
```

### ② 생성 전 승인 요청

```markdown
**PR 초안** : [Title]
- 병합 : `[대상 브랜치]` ← `[작업 브랜치]` / Assignee : [사용자]
- 미검증 항목 : [사용자 확인이 필요한 항목]

(PullRequestTemplate 양식 본문)

이대로 생성할까요?
```

### ③ 생성 완료 보고

```markdown
**PR 생성 완료** : #[번호] [Title]
- 링크 : [URL]
- 관련 이슈 : #[번호] (머지 시 자동으로 닫힘)
```
