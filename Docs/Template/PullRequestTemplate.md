# PullRequest Template

> PullRequest 작성시 활용하는 문서 양식이다.
> PUllRequest를 작성할 때에는 작업 내용에 따라서 Feat, Fix, Refactor 태그를 활용한다.

## 관련 이슈

> 해당 PullRequest가 해결하는 이슈 번호를 `close` 뒤에 작성한다.

- close #

## 요청 전 확인사항

> PullRequest가 유효한지 검사한다.

- [ ] `main` 혹은 `Develop` 브랜치와 충돌을 일으키지 않는다.
- [ ] 콘솔에서 에러 / 경고가 발생하지 않는다.
- [ ] `.meta` 확장자 파일이 함께 커밋되고 있다.
- [ ] PR과 연관된 올바른 이슈를 닫고 있다.

## 작업 내용

>  브랜치에서 구현한 기능에 대해 스크립트 단위로 설명을 진행한다. 수정한 스크립트에 대해서도 똑같이 진행한다.
>
>  구현한 기능을 먼저 설명하고, 수정된 기능을 설명한다.

### 1. 예시 기능 구현 (`Example.cs`)
1. 기능 구현 이유 (왜 구현 하였는가?)
2. 구현 방법, 방향성 설명 (어떻게 구현 하였는가?)
3. 사용 방법 (어떻게 사용하는가?)

### 2. 예시 기능 수정 (`Example.cs`)
1. 기능 수정 이유 (왜 수정 하였는가?)
2. 수정 방법, 방향성 설명 (어떻게 수정 하였는가?)
3. 사용 방법 (어떻게 사용하는가?)

## 확인 방법

> 작성된 내용대로 수행하면 리뷰어가 테스트 결과를 확인할 수 있도록 작성한다.

### 확인 위치

> 확인 위치는 `Assets/` 부터 작성하며, 생성 혹은 수정한 사항이 없는 것은 적지 않고 비워둔다.

- Scene : `Scene 파일 경로`
- Prefab : `Prefab 경로`
- Scripts : `Example.cs 경로`, `Example.cs 경로`

### 확인 순서

> 어떤 경로로, 어떤 절차에 따라 진행 하면 같은 환경에서 같은 결과를 얻을 수 있는지 차례대로 작성한다.

1. 환경 확인
2. 실행 절차
