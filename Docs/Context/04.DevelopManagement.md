## D. 개발 관리

### (1) 기술 적용 규칙
1. 오버 엔지니어링 하지 않는다
- 단순히 코드 한 두 줄로 끝낼 수 있는 상황에서 기법을 적용하는 것은 다시 한 번 고려 할 필요가 있다.
- 그럼에도 불구하고, 디자인 패턴 등을 도입해야 한다면 그 이유를 기술하도록 한다.

2. 기술 적용안이 생겼다면, 명세를 작성한다.
- 작성할 컴퍼넌트를 정리한 후, 명세 양식에 맞추어 문서를 작성 후 보고한다.

3. 명세가 승인되면 해당 명세를 토대로 작업을 진행한다.

### (2) 테스트 확인 규칙
- 한 기능을 개발했다면, 콘솔 출력 혹은 테스트 객체 제작 후 실제 게임 씬에서의 작동 확인 등의 산출물이 존재해야 한다.
- 테스트를 하기 위한 씬은 기능 별로 따로 구비한다.

### (3) 기능 구현 완료 조건
- 테스트가 정상적으로 완료되었을 때 보고하고, 승인 이후에 완료 처리한다.
